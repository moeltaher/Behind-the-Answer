# خلف الإجابة

لعبة متصفح تفاعلية تأخذ المستخدم عبر ثماني مراحل لعب: استخراج المواد، تصنيع المكونات، مراكز البيانات، تجهيز مواد البيانات، عمل التصنيف البشري، post-training، التقييم والجاهزية، ثم تشغيل الخدمة. بعد ذلك تأتي خاتمة مستقلة تعيد المستخدم إلى الطلب والإجابة وتختبر نقل الفكرة إلى منتج تقني مختلف.

## مبدأ التصميم التعليمي

لا تفترض اللعبة معرفة مسبقة بسلسلة الذكاء الاصطناعي. الحلقة الأساسية هي:

`شخص → مهمة → قيد أو حدث → قرار → أثر مرئي → ناتج تقني مختصر`

تفرق اللعبة بين **ترتيب اللعب** و**بنية النظام**. شريط المراحل خطي للتعلم، بينما الخاتمة تعيد رسم النظام إلى مسار مادي طويل الأجل، ودورة تطوير متكررة، وتشغيل مستمر. لا توجد درجة كلية خفية تجمع العمل والحقوق والجودة والموثوقية في رقم واحد.

كل مشهد يعرض عنصر **«مهمتك الآن»**. حالة اللوحة مشتقة من العمل المتبقي فعلًا: لا تعلن اكتمال نتيجة المصنع بينما دين الصيانة مفتوح، ولا اكتمال عطل التبريد قبل الإصلاح وإعادة الاختبار، وتتحول اختبارات checkpoint وتحدي نقل التعلم إلى «مكتمل» بعد إغلاقهما فعلًا.

## التشغيل

المشروع يعمل بالكامل داخل المتصفح: لا خادم خلفي، ولا قاعدة بيانات، ولا خطوة بناء، ولا تبعيات تشغيل خارجية.

أثناء التطوير:

```bash
python3 -m http.server 8000
```

ثم افتح `http://localhost:8000`.

توجد تبعيات تطوير واختبار فقط في `package.json`.

```text
index.html

css/
```

منطق كل مرحلة يوجد داخل ملفها في `js/scenes/`. لا توجد طبقة post-render تعيد كتابة المشهد بعد رسمه؛ لكل ميكانيكية مصدر حقيقة واحد.

## الخصوصية والحفظ

لا ترسل اللعبة بيانات إلى أي خادم. التقدم والإعدادات تحفظ فقط في `localStorage` ويمكن حذفها من إعدادات اللعبة.

الحالة الحالية تستخدم `schemaVersion: 5`. طبقة التخزين تتحقق من القيم والعلاقات السببية ومن اتساق المشهد الحالي مع التقدم. يوجد migration من v4 وv3 وv2 والإصدارات الأقدم.

إذا كان حفظ قديم قد وصل إلى post-training أو ما بعده، يعاد اللاعب إلى `trainingSetup` مع الاحتفاظ بالتقدم السابق الممكن إثباته؛ لأن v5 يشترط أدلة إعداد مرتبطة بكل revision وقرارًا صريحًا لفجوة المرونة قبل الانتقال إلى الحادث التشغيلي. أما حفظ v4 السابق لـpost-training فيبقى في موضعه إذا كان متسقًا، بما في ذلك حالة دين صيانة أُغلق بالفعل.

## الدقة التقنية والمنطقية

- التعدين يجعل تأجيل فحص القطاع الأسرع مفاضلة فعلية، ولا يخترع إصابة عشوائية لصناعة العقوبة.
- المصنع يفصل جودة الوحدات عن **دين الصيانة**؛ إذا أكمل اللاعب الدفعة بعد التنبيه، يمكنه تنفيذ الصيانة وإغلاق السبب أو ترحيل الدين صراحة.
- في مركز البيانات، نقل workload يحافظ على الاستمرارية لكنه لا يصلح المجموعة الأصلية. لا تصبح القدرة جاهزة قبل إصلاح التبريد وإعادة الاختبار.
- مرحلة البيانات تفصل بين مرور المادة في workflow وبين حسم الحقوق والخصوصية والملاءمة.
- قبل post-training تسجل `dataTrainingApproved` السماح الصريح لمادة غير محسومة، و`dataTrainingHeld` ما أوقف قبل المعالجة.
- `dataCurrentTrainingUsed` يمثل المواد الموجودة في revision الحالية، بينما `dataTrainingUsed` سجل تاريخي لا يُمحى إذا خرجت المادة من نسخة لاحقة.
- **إنشاء revision الجديدة يحدث فقط عند بدء جولة post-training فعلية.** إذا استُبعدت مادة مستخدمة عند بوابة الإصدار، تبطل صلاحية أدلة النسخة الحالية وتعود اللعبة إلى `trainingSetup` من دون زيادة رقم revision. عند بدء الجولة التالية فقط يزيد الرقم وتُسجل قرارات الحوسبة والـcheckpoint للنسخة الجديدة.
- لا ترث revision التالية إعدادات الحوسبة أو checkpoint القديمة بصمت بعد تغيير المدخلات؛ يعاد عرض الإعداد ويجب تأكيده من جديد.
- طبقة التخزين ترفض أي حالة داخل `trainingRun` أو ما بعده إذا لم يكن إعداد الحوسبة والـcheckpoint موثقًا للـrevision الحالية.
- يسمح `ledger` بأكثر من سجل للفصل نفسه عندما تتكرر دورة التطوير، ويعرض الأحدث أولًا مع تاريخ revisions السابقة.
- لا يمكن بدء post-training بلا أي مدخل بيانات مؤهل ولا مثال تصنيف بشري مؤكد.
- عامل التصنيف يرى دليل المشروع قبل العمل. **المبلغ قبل مراجعة الجودة لا يستخدم قرار المراجع المخزن داخليًا**، حتى لا تكشف الواجهة نتيجة المراجعة قبل دخول المراجع نفسه.
- بعد مهام تقييم النموذج توجد خطوة معايرة للمقيّم قبل استخدام تقييمه كدليل. إذا أخطأ المقيّم، يجب أن ينجح في عينة تحقق جديدة.
- تقييم checkpoint مقارنة فعلية لثلاثة أمثلة، ولا تفترض اللعبة أن النسخة الأحدث أفضل لمجرد حداثتها.
- إصلاح خلل السلامة وإعادة اختباره إلزاميان قبل الجاهزية.
- بوابة السلامة والخصوصية وحوكمة البيانات لا يمكن اعتمادها إذا كانت revision الحالية تحتوي مادة ذات مسألة حوكمة غير محسومة.
- بوابة السعة تعرض أولًا نتيجة 92% مقابل حد تنبيه 90%، فلا يمكن اعتمادها حتى التحقيق وإعادة القياس إلى 84% في السيناريو.
- الأعمال الإضافية في بوابة الإصدار تشرح سبب ظهورها، وما ينقل إلى المراقبة يجب تنفيذه بعد الإطلاق قبل متابعة التشغيل.
- توزيع الحمل يقبل عدة حلول صحيحة. اختبار N-1 يضيف حد استقبال طوارئ مقداره 20 نقطة لكل مركز باقٍ. مع حمل إجمالي 100% والسعات 60/45/35، **الحد الأقصى الرياضي الممكن هو تحمل حالة واحدة من ثلاث**. عند 1/3 لا تعرض اللعبة إعادة توزيع وهمية؛ عند 0/3 يمكن إعادة التوزيع للوصول إلى 1/3. الاستمرار بمرونة ناقصة يتطلب تسجيل قبول فجوة المرونة صراحة للتوزيع الحالي.
- طبقة التخزين لا تقبل الوصول إلى الحادث أو الاستعادة بتوزيع ذي فجوة مرونة من دون `deploy-resilience-risk-*` مطابق لذلك التوزيع.
- العطل التشغيلي اللاحق لا يُنسب تلقائيًا إلى توزيع الحمل أو إلى الفحوص المؤجلة؛ التشخيص هو الذي يحدد المشتبه الرئيسي.
- الخاتمة تعرض lineage البيانات وما هو حالي أو تاريخي أو موقوف أو معلق.
- الأدوار الداعمة في النتائج تظهر بصريًا كبطاقات أشخاص/فرق، وتُكيّف مع المسار. مراجع اللغة لا يظهر إذا التقط اللاعب خلل السلامة من أول مرة، ويظهر إذا احتاجت الحالة إلى مراجعة بشرية ثانية.
- تحدي RAG يشرح لكل عنصر خاطئ لماذا ينتمي إلى زمن مختلف.
- سجل النتائج الكامل يعرض كل `state.decisions`، وبطاقات الملخص تفضل أحدث قرار مطابق للأولوية.

## الوصول

- RTL أساسي.
- الانتقال بين المشاهد ينقل التركيز إلى عنوان المشهد الجديد.
- إعادة رسم المشهد نفسه لا تترك التركيز على عنصر حُذف؛ ينتقل إلى feedback ظاهر أو العنوان.
- رسائل feedback المحددة تستخدم `role="status"` عند الحاجة.
- المرحلة الحالية تحمل `aria-current="step"`.
- عند عدم وجود اختيار محفوظ، يبدأ تقليل الحركة من `prefers-reduced-motion`.
- الحوارات تحمل أسماء واضحة لقارئات الشاشة ومناطق التمرير الأفقية قابلة للوصول بلوحة المفاتيح.
- على الشاشات الصغيرة تبدأ المشاهد من أعلى حتى تبقى لوحة «مهمتك الآن» وأزرار المتابعة مستقرة عند تغير طول المحتوى.

## التحقق الآلي

Workflow `Validate static game` يشغل:

- `npm audit --audit-level=high`
- فحص JavaScript syntax وESLint
- سلامة البنية والمراجع
- schema v5 وعلاقات الحفظ السببية
- سلامة CSS
- رحلة متصفح كاملة على desktop وmobile
- اختبارات causality وmigration وfocus والوصول
- smoke checks على Firefox وWebKit
- regression suites للجولات الثالثة والرابعة والخامسة والسادسة والسابعة

الجولة السابعة موثقة بالتفصيل في `docs/SEVENTH-AUDIT-VERIFICATION.md`.
