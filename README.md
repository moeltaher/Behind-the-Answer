# خلف الإجابة

لعبة متصفح تفاعلية تأخذ المستخدم في رحلة من استخراج المواد وصناعة الأجهزة إلى مراكز البيانات والبيانات وتدريب النموذج والمراجعة البشرية وتشغيل الخدمة، بهدف كشف العمل البشري والبنية المادية خلف أنظمة الذكاء الاصطناعي.

## مبدأ التصميم التعليمي

لا تفترض اللعبة أن المستخدم يعرف سلسلة إمداد الذكاء الاصطناعي أو مصطلحاتها. قبل كل مرحلة تشرح باختصار أين نحن، وما علاقة المرحلة بالإجابة، ومن يعمل فيها، وما المهمة المطلوب تنفيذها. أثناء المهمة تميز الواجهة بين الاختيارات التي تمثل جزءًا من العمل نفسه وبين القرارات التي تظهر بسبب حدث أو قيد جديد.

تظهر خريطة الرحلة باستمرار، وتُعرَّف المصطلحات مثل «النموذج» و«الخادم» و«التدريب» قبل الاعتماد عليها. الواجهة والنصوص الموجهة للاعب عربية.

## التشغيل

المشروع يعمل بالكامل داخل المتصفح: لا خادم خلفي، ولا قاعدة بيانات، ولا خطوة بناء، ولا تبعيات تشغيل خارجية.

ولأن الكود مقسم إلى وحدات JavaScript، استخدم خادم ملفات محليًا أثناء التطوير:

```bash
python3 -m http.server 8000
```

ثم افتح:

```text
http://localhost:8000
```

- `js/core/`: المحرك العام: الحالة، التخزين المحلي، المقاييس، التنقل، الصوت، دفتر السلسلة وقابلية الوصول.
- `js/data/chapters.js`: تعريف المراحل التسع ومحتواها التعليمي وتسميات خط الرحلة.
- `js/data/content-tasks.js`: أمثلة مهام البيانات والتصنيف والتقييم والدعم.
- `js/data/story.js`: العناصر السردية المشتركة، ومنها الطلب التجريبي الثابت.
- `js/data/characters.js` و`supporting-actors.js`: الشخصيات الرئيسية والأدوار البشرية المساندة.
- `js/data/stage-tasks.js`: تعريف المهمة الأساسية لكل مرحلة وشروطها وقيودها.
- `js/data/stage-backgrounds.js`: المصدر المركزي لربط المشاهد بالمراحل والخلفيات.
- `js/components/`: عناصر مشتركة مثل بطاقات الشخصيات، التقدم، الإرشاد، شاشة نهاية المرحلة، والحوارات.
- `js/scenes/`: التفاعلات الخاصة بكل مرحلة رئيسية.
- `tests/`: فحوص البنية والرحلة الكاملة.

لشرح تفصيلي لمسؤولية كل جزء وقواعد إضافة مشاهد جديدة، راجع `docs/CODE-STRUCTURE.md`.

## الخصوصية

لا ترسل اللعبة بيانات إلى أي خادم. التقدم والإعدادات تحفظ فقط في `localStorage` داخل المتصفح ويمكن حذفها من إعدادات اللعبة.

الحالة المحفوظة تستخدم بنية النسخة الحالية فقط. إذا لم تطابق البيانات المخزنة البنية المتوقعة، تستخدم اللعبة القيم الافتراضية للحقل المتأثر بدل تشغيل منطق تحويل أو توافق مع إصدارات أخرى.

## الدقة التقنية

تفرق اللعبة بين بناء النظام سابقًا وبين ما يحدث عند استخدامه. التعدين والتصنيع وتجهيز البيانات والتدريب لا تتكرر مع كل طلب. عند إرسال المستخدم طلبه، تعتمد الإجابة على بنية ونموذج بُنيا مسبقًا وعلى الخوادم والخدمات التي تعمل في اللحظة الحالية.

## التحقق الآلي

يوجد GitHub Actions workflow باسم `Validate static game` يعمل مع Pull Requests وعلى فرع `main`. يتحقق من:

- سلامة صياغة جميع ملفات JavaScript وملفات الاختبار.
- سلامة الاستيرادات المحلية ومراجع CSS/JavaScript من `index.html`.
- عدم وجود ملفات JavaScript تشغيلية أو ملفات CSS أو أصول صور غير مستخدمة.
- تطابق جميع المشاهد المسجلة مع خريطة المراحل.
- مرور الرحلة كاملة عبر Playwright على سطح المكتب والهاتف.
- ظهور المهمة والأحداث والقرارات والشخصيات الثانوية في مواضعها المتوقعة.
- بقاء لوحة المهمة Sticky على الهاتف.

اللعبة نفسها لا تحتاج أي مكتبة خارجية وقت التشغيل؛ Playwright يثبت داخل CI لأغراض الاختبار فقط.
