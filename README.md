# خلف الإجابة

لعبة متصفح تعليمية تكشف العمل البشري والبنية المادية والتنظيمية التي تختصرها واجهة الذكاء الاصطناعي في إجابة تبدو فورية.

يمر اللاعب عبر ثماني مراحل: المواد، تصنيع المكونات، مراكز البيانات، تجهيز مواد البيانات، التصنيف البشري، التدريب الإضافي، التقييم والجاهزية، ثم تشغيل الخدمة. بعد ذلك تعيد الخاتمة رسم ما حدث إلى ثلاثة مسارات متداخلة: بناء مادي طويل الأجل، دورة تطوير متكررة، وتشغيل مستمر.

## مبدأ التصميم

الحلقة الأساسية هي:

`شخص → مهمة → قيد/حدث → قرار → عمل أو دليل → أثر مرئي → اختصار تقني`

ترتيب المراحل ترتيب تعليمي، وليس وصفًا هندسيًا يقول إن التعدين والتصنيع والتدريب تتكرر عند كل طلب.

القاعدة المنهجية الأهم: **القرار لا يساوي تنفيذ العمل الذي ينشأ عنه.** لذلك:

- إيقاف اختبار مركز البيانات لا يصلح التبريد تلقائيًا؛ يجب تنفيذ الإصلاح والتحقق وإعادة الاختبار.
- التوقف في جولة التدريب لا يعيد مجموعة الحوسبة تلقائيًا.
- تشخيص ارتفاع الذاكرة لا يخفض القياس قبل تعديل الإعداد وإعادة القياس.
- `restart` أو `rollback` لا يثبتان عودة الخدمة قبل التحقق الصحي.
- مراجعة ترخيص لا تحسم الحقوق قبل ظهور الدليل واعتماده.

## ما تغير في البنية الحالية

- **حالة مسار البيانات مستقلة عن الأدلة.** `ready / pending / excluded` لا تعيد كتابة ما كان معروفًا عن الحقوق والخصوصية والملاءمة.
- **الحوسبة ليست اختيارًا شكليًا.** المشروع يخصص 8 مجموعات في السيناريو، والقرار الحقيقي عند العطل هو التوقف للإصلاح أو الاستمرار عند الحد الأدنى مع دين تحقق للاستقرار.
- **معالجة حواجز البيانات حسب المشكلة.** ترخيص الكود يُراجع بالدليل، وبيانات الاتصال يمكن تنقيحها مع إعادة التدريب، بينما الاستبعاد يستخدم عندما لا يمثل السيناريو معالجة كافية.
- **قرار الإصدار لا يعني فتح الخدمة.** بعد اعتماد النسخة يجب تجهيز توزيع التشغيل واختبار المرونة، ثم تُفتح حركة المستخدمين.
- **الفحوص المؤجلة دين تشغيل حقيقي.** إذا نُقلت للمراقبة تظهر نافذة تكون فيها الخدمة عاملة والفحص ما زال مفتوحًا، ثم يُنفذ ويُغلق.
- **السلامة في هذا السيناريو طبقة سياسة استجابة.** إصلاحها لا يغير أوزان النموذج، لكنه يحتاج إعادة اختبار وبوابة انحدار.

## التشغيل محليًا

المشروع HTML/CSS/JavaScript باستخدام ES modules أصلية. لا توجد خطوة build، ولا backend، ولا قاعدة بيانات، ولا حساب مستخدم.

```bash
python3 -m http.server 4173
```

ثم افتح `http://127.0.0.1:4173/`.

## الحفظ والخصوصية

التقدم وإعدادات الوصول تحفظ في `localStorage` فقط. لا يرسل الطلب التجريبي إلى خادم خارجي. مخطط الحالة الحالي هو **schema v5**، مع مسارات ترحيل للحفظ القديم حتى لا يفقد المستخدم تقدمه بلا داعٍ.

## بنية المشروع

- `index.html`: صفحة التشغيل الوحيدة.
- `js/app.js`: ربط المكونات والمسارات والحالة.
- `js/scenes/`: منطق المشاهد.
- `js/domain/game-rules.js`: قواعد المجال المشتركة للحوسبة والحوكمة والمرونة.
- `js/data/`: المحتوى وتعريفات المراحل والشخصيات.
- `js/components/`: مكونات واجهة قابلة لإعادة الاستخدام.
- `js/core/`: التخزين، الحالة، التوجيه، السجل، القرارات والوصول.
- `css/`: نظام العرض الحالي فقط؛ لا توجد طبقات patch تاريخية.
- `tests/`: فحوص static/schema/CSS ومتصفح وregression.
- `docs/`: التصميم والمنهجية والسرد والمعمارية وسجل المراجعات.

## التحقق

```bash
npm ci --ignore-scripts
npm run audit:ci
npm run check:syntax
npm run check:lint
npm run check:static
npm run check:storage
npm run check:css
npm run test:browser
npm run test:regression:data-governance
npm run test:regression:revisions-failover
npm run test:regression:guidance-history
npm run test:regression:causality-results
npm run test:regression:state-roles
npm run test:regression:clarity-remediation
```

الـCI يشغل الرحلة الكاملة على Chromium، ويفحص الهاتف، والوصول باستخدام axe، ثم smoke على Firefox وWebKit.
