# خلف الإجابة

لعبة متصفح تفاعلية تأخذ المستخدم في رحلة من استخراج المواد وصناعة الأجهزة إلى مراكز البيانات والبيانات وتدريب النموذج والمراجعة البشرية وتشغيل الخدمة، بهدف كشف العمل البشري والبنية المادية خلف أنظمة الذكاء الاصطناعي.

## مبدأ التصميم التعليمي

لا تفترض اللعبة أن المستخدم يعرف سلسلة إمداد الذكاء الاصطناعي أو مصطلحاتها. قبل كل مرحلة تشرح باختصار:

- أين نحن في الواقع.
- ماذا يحدث في هذه المرحلة.
- لماذا يحتاج الذكاء الاصطناعي إلى هذه المرحلة.
- من يعمل هنا.
- ما الذي ستنتجه المرحلة وما الذي ينتقل بعدها إلى المرحلة التالية.

تظهر خريطة الرحلة باستمرار، وتُعرَّف المصطلحات مثل «النموذج» و«الخادم» و«التدريب» قبل الاعتماد عليها. الواجهة والنصوص الموجهة للاعب عربية.

## التشغيل

المشروع يعمل بالكامل داخل المتصفح: لا خادم خلفي، ولا قاعدة بيانات، ولا خطوة بناء، ولا مكتبات خارجية.

ولأن الكود مقسم إلى وحدات JavaScript، استخدم خادم ملفات محليًا أثناء التطوير:

```bash
python3 -m http.server 8000
```

ثم افتح:

```text
http://localhost:8000
```

## بنية المشروع

```text
index.html
assets/
  images/
    characters/
    scenes/
css/
  variables.css
  base.css
  layout.css
  components.css
  scenes.css
  education.css
  characters.css
  stage-backgrounds.css
  abstraction.css
  data-types.css
  ending.css
  accessibility.css
  responsive.css
js/
  app.js
  core/
  data/
  components/
  scenes/
docs/
.github/workflows/
```

- `js/core/`: الحالة، التخزين المحلي، المقاييس، التنقل، الصوت، دفتر السلسلة وقابلية الوصول.
- `js/data/`: محتوى المراحل والمهام، الشخصيات، وربط المشاهد بالخلفيات.
- `js/components/`: عناصر مشتركة مثل بطاقات الشخصيات، التقدم، خريطة الرحلة، شاشات نهاية المراحل والحوارات.
- `js/scenes/`: ملف مستقل لكل مرحلة رئيسية من اللعبة.
- `assets/images/characters/`: الرسومات الكرتونية للشخصيات.
- `assets/images/scenes/`: الخلفيات المرسومة للمراحل.
- `css/`: التصميم العام والمكونات والمشاهد والوصول والاستجابة للشاشات المختلفة.
- `docs/`: التصميم السردي والمنهجية والملاحظات التقنية وتوثيق بنية الكود.

لشرح تفصيلي لمسؤولية كل جزء وقواعد إضافة مشاهد جديدة، راجع `docs/CODE-STRUCTURE.md`.

## الخصوصية

لا ترسل اللعبة بيانات إلى أي خادم. التقدم والإعدادات تحفظ فقط في `localStorage` داخل المتصفح ويمكن حذفها من إعدادات اللعبة.

تحميل الحالة متوافق مع الحقول الجديدة التي قد تضاف في تحديثات لاحقة، كما توجد ترحيلات للتسميات القديمة المحفوظة من إصدارات سابقة.

## الدقة التقنية

تفرق اللعبة بين بناء النظام سابقًا وبين ما يحدث عند استخدامه. التعدين والتصنيع وتجهيز البيانات والتدريب لا تتكرر مع كل طلب. عند إرسال المستخدم طلبه، تعتمد الإجابة على بنية ونموذج بُنيا مسبقًا وعلى الخوادم والخدمات التي تعمل في اللحظة الحالية.

## التحقق الآلي

يوجد GitHub Actions workflow باسم `Validate static game` يعمل مع Pull Requests وعلى فرع `main`، ويتحقق من:

- سلامة صياغة جميع ملفات JavaScript.
- وجود ملفات CSS وJavaScript المحلية المشار إليها من `index.html`.

لا يحتاج هذا الفحص إلى تثبيت أي مكتبات للمشروع.
