# التحقق من جولة المراجعة الثالثة

توثق هذه الصفحة المشكلات التي كشفتها الجولة الثالثة بعد دمج إصلاحات الجولة الثانية، وكيف أصبحت كل مشكلة ممثلة في الكود والاختبارات.

## 1. أهلية البيانات قبل post-training

لم يعد مرور المادة في workflow كافيًا لإدخالها إلى التطوير. المادة `ready` التي تحمل مسألة غير محسومة تظهر في `trainingSetup` كقرار مستقل: إيقافها قبل المعالجة أو تجاوز الحاجب بقرار صريح. يحفظ `dataTrainingHeld` ما أوقف، ويحفظ `dataTrainingUsed` ما عولج فعلًا.

## 2. لا يوجد زر سحري يحول كل unresolved إلى clear

عند الجاهزية تعتمد المعالجة على نوع الحالة. مثال الشفرة البرمجية يحسم الحقوق عبر دليل ترخيص محدد في السيناريو. أما المادة التي عولجت بالفعل ولا يمكن حسم حاجبها بهذا الدليل، فتتطلب التخلص من النسخة الناتجة وإعادة الجولة دون المادة. يبقى index المادة في `dataTrainingUsed` حتى بعد استبعادها من النسخة الجديدة، لأنه سجل تاريخي لما حدث.

## 3. مخطط حالة v3 ومهاجر v2

`STATE_SCHEMA_VERSION` أصبح 3. الحفظ من v2 الذي وصل إلى التدريب أو ما بعده يعود إلى `trainingSetup` مع الاحتفاظ بالتقدم السابق الممكن إثباته. لا تُعتبر قرارات launch/deployment القديمة دليلًا على اجتياز أهلية البيانات أو checkpoint أو بوابات الأدلة أو N‑1 التي لم تكن v2 تحفظها.

## 4. مصدر حقيقة واحد

حُذف `js/core/audit-enhancements.js`. إصلاحات المصنع والتصنيف وcheckpoint والإصدار والـfailover والنهاية أصبحت في ملفات المشاهد الأصلية. `app.js` لا ينفذ post-render patch بعد `router.html`.

## 5. بوابات إصدار قائمة على أدلة

كل بوابة تعرض نتيجة يمكن تفسيرها. بوابة السعة تبدأ بذروة ذاكرة 92% مقابل حد تنبيه 90%، ولا يمكن اعتمادها مباشرة. يجب التحقيق، ثم تظهر إعادة القياس 84% قبل إمكانية اعتماد البوابة. بقية البوابات تعرض أدلتها أيضًا بدل تحويل أسمائها إلى checklist.

## 6. عدم ادعاء اختبار أمني غير موجود

أزيل لفظ «الأمن» من البوابة الثالثة. الاسم الحالي «السلامة والخصوصية وحوكمة البيانات» يطابق ما تعرضه اللعبة فعلًا بدل الإيحاء بوجود اختبار cybersecurity لم تتم محاكاته.

## 7. استبدال إجمالي headroom باختبار N‑1

أزيل مؤشر «إجمالي الهامش المتاح» باعتباره مقياسًا للمرونة؛ فهو ثابت عند 40 نقطة لأي توزيع صالح لأن مجموع السعات 140 والحمل 100. بعد اعتماد التوزيع يختبر اللاعب خروج كل مركز على حدة، ويقارن حمله بالهامش المتاح في المركزين الآخرين. تحفظ `deployFailoverChecks` الحالات المنفذة وتستخدم النتيجة لاحقًا كتفسير للمرونة لا لسبب الحادث.

## 8. السجل الكامل يعرض كل القرارات

أصبحت شاشة النتائج تستخدم `decisionCategory()` مركزيًا مع fallback باسم «قرارات أخرى». تشمل فئة التطوير `checkpoint-*` و`release-*` و`extra-check-*`. اختبار المتصفح يقارن عدد `.decision-row` بعدد `state.decisions` حتى لا يسقط قرار جديد بصمت.

## 9. checkpoint كتقييم فعلي

`checkpointEval` يعرض ثلاث مقارنات نواتج: اعتذار قصير، تلخيص قانوني، ورسالة ودية. التحسين المستهدف يظهر في بعض الحالات، بينما الاختصار يضر قيدًا قانونيًا في حالة أخرى. لا يكتمل التقييم إلا بعد تفسير الأمثلة وفق الطلب، ثم يسجل `checkpointEvalComplete`.

## 10. اختبارات migration/reload/accessibility

`tests/smoke.mjs` يغطي رحلة كاملة desktop/mobile، وحالات سببية منفصلة، وإعادة تحميل بعد أهلية البيانات وبوابة الإصدار وfailover، وmigration v2 داخل المتصفح، ومصفوفة axe للمشاهد الديناميكية. `tests/third-audit.mjs` يضيف regression مركزًا لكل محاور هذه الجولة.

## 11. اتساق state machine

أضيفت علاقات لا تسمح بوجود توزيع تشغيل قبل launch صالح، أو recovery قبل توزيع + ثلاثة اختبارات failover + التشخيص، أو transfer قبل recovery ومعالجة بلاغي الدعم. كما أن المادة held لا تعامل كحاجب إصدار لأنها لم تدخل post-training، بينما المادة used/unresolved تفعل ذلك.

## مصفوفة التحقق المطلوبة قبل الدمج

- `npm audit --audit-level=high`
- `npm run check:syntax`
- `npm run check:lint`
- `npm run check:static`
- `npm run check:storage`
- `npm run check:css`
- `npm run test:browser`
- `npm run test:third-audit`

لا تعد هذه الوثيقة النجاح دليلًا بذاته؛ المرجع النهائي هو نجاح دورة GitHub Actions على head نفسه الذي سيدخل المراجعة.
