# بنية الكود

هذه الوثيقة تصف البنية الحالية للعبة فقط، وتحدد مسؤولية كل جزء حتى يظل مصدر الحقيقة واضحًا ولا تتراكم ملفات أو مسارات منطقية غير مستخدمة.

## `index.html`

يحتوي هيكل الصفحة الثابت: شريط اللعبة، حاويات المشهد، النوافذ الحوارية، ومراجع ملفات CSS وJavaScript. لا يوضع منطق اللعبة أو محتوى المراحل هنا.

## `js/app.js`

نقطة تشغيل التطبيق. ينشئ الحالة والإعدادات، يربط الوحدات المشتركة، يسجل مسارات المشاهد، ويضيف طبقة الإرشاد الموحدة قبل محتوى كل مشهد.

## `js/core/`

محرك عام لا يعرف تفاصيل القصة:

- `state.js`: شكل الحالة الافتراضية والمساعدات العامة.
- `storage.js`: حفظ واستعادة شكل الحالة والإعدادات الحاليين من `localStorage`.
- `router.js`: الانتقال والرسم بين المشاهد.
- `metrics.js`: تطبيق آثار القرارات على المؤشرات.
- `ledger.js`: دفتر السلسلة.
- `audio.js`: أصوات الواجهة الاختيارية.
- `accessibility.js`: إعدادات الوصول.

لا تضف إلى `DEFAULT_STATE` قيمة يمكن اشتقاقها من بيانات أخرى. تحفظ الحالة فقط ما يجب أن يبقى بعد إعادة تحميل الصفحة.

## `js/data/`

- `chapters.js`: المراحل التسع ومفاهيمها وتسميات خط الرحلة.
- `content-tasks.js`: عناصر مراجعة البيانات، مهام التصنيف، مقارنات التقييم وبلاغات الدعم.
- `story.js`: عناصر سردية مشتركة مثل الطلب التجريبي.
- `characters.js`: الشخصيات الرئيسية وربطها بالمشاهد.
- `supporting-actors.js`: الشخصيات والأدوار البشرية الثانوية.
- `stage-tasks.js`: المهمة الأساسية لكل مرحلة وطريقة تنفيذها وشرط انتهائها وقيدها.
- `stage-backgrounds.js`: خريطة المشهد إلى المرحلة وربط المراحل بالخلفيات.

أي بيانات جديدة توضع في الوحدة المتخصصة بها، ولا ينشأ ملف جامع موازٍ للمصادر الحالية.

## `js/components/`

- `character-card.js`: بطاقات الشخصيات الرئيسية وشبكة الشخصيات.
- `progress.js`: تقدم الرحلة ومقدمات المراحل.
- `abstraction.js`: شاشة تحول العمل إلى ناتج مختصر.
- `hud.js`: مؤشرات العرض العامة.
- `dialogs.js`: النوافذ الحوارية.
- `task-flow.js`: واجهة المهمة والحدث والقرار والنتيجة والأطراف.
- `scene-guidance.js`: يربط المشهد بمهمته وأطرافه وأحداثه ونتائجه.

لا تكرر HTML لمكوّن مشترك داخل ملفات المراحل.

## قواعد تصميم المهام

كل مرحلة تعرض بوضوح:

1. **مهمتك الآن**: الفعل المطلوب من اللاعب.
2. **كيف تنفذها؟**: الطريقة العملية.
3. **متى تنتهي؟**: شرط الاكتمال.
4. **القيد**: الوقت أو الجودة أو الأجر أو أي عامل يحد الاختيار.
5. **الحالة**: جارية، قرار مطلوب، استؤنفت، أو مكتملة.

إذا ظهر موقف جديد أثناء المهمة، يعرض التسلسل بصريًا:

`تقدم المهمة → حدث أثناء/بعد المهمة → معنى الحدث → قرار مطلوب → نتيجة القرار → استكمال أو إكمال المهمة`

لا تستخدم علاقة سببية إلا عندما يثبتها السيناريو. الخيارات التي تمثل المهمة نفسها توصف صراحة بأنها اختيار لإكمال المهمة وليست حادثًا طارئًا.

## قواعد إظهار الأشخاص والجهات

- أي شخص يعطي أمرًا، يفرض موعدًا، يحذر العامل، يراجع عمله، يرفضه، أو يتأثر بقراره يظهر بصريًا.
- الشخصية الرئيسية تستخدم بطاقة الشخصية وصورتها.
- الشخصيات الثانوية والفرق تستخدم `actorStrip` أو `actorMessage`.
- المنصة أو النظام أو القيد المؤسسي يستخدم `institutionCard` ولا يمثل بوجه بشري.
- لا يعتمد ربط الشخصية بصورتها على ترتيبها داخل قائمة.

## `js/scenes/`

كل ملف يمثل مرحلة رئيسية واحدة ويحتوي المشاهد والتفاعلات الخاصة بها فقط.

عند إضافة مشهد جديد:

1. أضفه في ملف المرحلة وأعده ضمن كائن المسارات.
2. أضفه إلى `SCENES_BY_STAGE` في `stage-backgrounds.js`.
3. اربط الشخصية الرئيسية في `characters.js` إذا لزم الأمر.
4. أضف أي دور ثانوي في `supporting-actors.js` واربطه في `scene-guidance.js`.
5. عرّف المهمة في `stage-tasks.js` إذا كانت مرحلة جديدة.
6. لا تضف حالة محفوظة إلا إذا كان استمرارها بعد إعادة التحميل مطلوبًا.
7. استخدم `content-tasks.js` بدل تكرار أمثلة المهمة.

## CSS

- `variables.css`: المتغيرات.
- `base.css`: العناصر الأساسية والطباعة.
- `layout.css`: هيكل الصفحة.
- `components.css`: المكونات العامة.
- `scenes.css`: عناصر اللعب الخاصة بالمشاهد.
- `education.css`: مقدمات المراحل والخريطة التعليمية.
- `characters.css`: صور وبطاقات الشخصيات.
- `task-flow.css`: المهمة والحدث والقرار والنتيجة والأشخاص والجهات.
- `stage-backgrounds.css`: الخلفيات وطبقة المقروئية.
- `abstraction.css`: شاشة نهاية المرحلة المشتركة.
- `data-types.css`: شبكة أنواع البيانات.
- `ending.css`: مشاهد الخاتمة.
- `accessibility.css`: أوضاع الوصول.
- `responsive.css`: قواعد الاستجابة.

لا يترك selector بعد حذف المكوّن الذي يستخدمه.

## قواعد عامة

- كل نص ديناميكي يمر عبر `escapeHtml` قبل حقنه في HTML.
- لا تستخدم قيمًا رقمية غير مقيدة في `style` مباشرة.
- لا تضف مكتبة خارجية وقت التشغيل لمشكلة يمكن حلها بواجهات المتصفح الأصلية.
- لا تجعل فشل الصوت أو التخزين المحلي يمنع استمرار اللعبة.
- مصدر الحقيقة واحد لكل مجال: المراحل في `chapters.js`، خريطة المشاهد في `stage-backgrounds.js`، والطلب التجريبي في `story.js`.
- لا يبقى ملف JavaScript تشغيلي أو ملف CSS أو أصل صورة بلا استخدام فعلي.

## التحقق الآلي

### `tests/static-integrity.mjs`

يفحص:

- صحة الاستيرادات المحلية.
- صحة مراجع CSS وJavaScript في `index.html`.
- عدم وجود ملفات JavaScript تشغيلية غير مستوردة.
- عدم وجود ملفات CSS غير مرتبطة بالصفحة.
- عدم وجود أصول صور غير مستخدمة.
- تطابق كل route مسجل مع خريطة المراحل وعدم وجود معرفات مشاهد مكررة.

### `tests/smoke.mjs`

يمر بالرحلة كاملة عبر Playwright على سطح المكتب والهاتف، ويختبر المهمة والأحداث والقرارات والشخصيات الثانوية والحفظ وإعادة التحميل والمسارات البديلة المهمة.

قبل دمج أي إعادة هيكلة يجب أن تنجح صياغة JavaScript والفحص الثابت ورحلة Playwright معًا.
