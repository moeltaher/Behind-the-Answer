# بنية الكود

هذه الوثيقة تحدد مسؤولية كل جزء من اللعبة حتى تبقى الإضافات المستقبلية منظمة ولا تعود اللعبة إلى ملف واحد كبير أو سلسلة من الإصلاحات المتراكبة.

## `index.html`

هيكل الصفحة الثابت فقط: شريط اللعبة، حاويات المشهد، النوافذ الحوارية، ومراجع ملفات CSS وJavaScript.

لا يوضع منطق اللعبة أو محتوى المراحل داخل هذا الملف.

## `js/app.js`

نقطة تشغيل التطبيق. مسؤول عن:

- إنشاء الحالة والإعدادات.
- ربط الوحدات المشتركة.
- تسجيل مسارات المشاهد.
- تحديث خلفية المرحلة والشخصية الحالية.
- إضافة طبقة الإرشاد الموحدة للمهمة قبل محتوى المشهد.

لا ينبغي إضافة محتوى سردي خاص بمرحلة هنا.

## `js/core/`

محرك عام لا يعرف تفاصيل قصة اللعبة:

- `state.js`: الحالة الافتراضية والمساعدات العامة.
- `storage.js`: الحفظ المحلي وترحيل البيانات القديمة.
- `router.js`: الانتقال والرسم بين المشاهد.
- `metrics.js`: مؤشرات القرارات.
- `ledger.js`: دفتر السلسلة.
- `audio.js`: أصوات الواجهة الاختيارية.
- `accessibility.js`: إعدادات الوصول.

## `js/data/`

بيانات ثابتة وليست منطق تفاعل:

- `game-data.js`: بيانات المراحل وأمثلة المهام.
- `characters.js`: الشخصيات الرئيسية وربطها بالمشاهد.
- `supporting-actors.js`: الشخصيات والأدوار البشرية الثانوية التي يجب أن تظهر بصريًا.
- `stage-tasks.js`: تعريف المهمة الأساسية في كل مرحلة، وطريقة تنفيذها وشرط انتهائها والقيد المحيط بها.
- `stage-backgrounds.js`: ربط المشاهد بالخلفيات.

إذا كان التغيير يتعلق بنص أو قائمة أمثلة أكثر من كونه سلوكًا، يفضّل وضعه هنا.

## `js/components/`

مكونات مشتركة تستخدمها مراحل متعددة، مثل:

- بطاقة الشخصية.
- شاشات التحول في نهاية المرحلة.
- عناصر القياس.
- تقدم الرحلة.
- النوافذ الحوارية.
- `task-flow.js`: لغة الواجهة الموحدة للمهمة والحدث والقرار والنتيجة والشخصيات والجهات المؤسسية.
- `scene-guidance.js`: يربط حالة كل مشهد بهذه المكونات ويحدد متى ظهر الحدث، ولماذا ظهرت الخيارات، ومن يشارك فيه.

لا تكرر HTML لمكوّن موجود داخل ملفات المراحل.

## قواعد تصميم المهام

كل مرحلة يجب أن تعرض بوضوح:

1. **مهمتك الآن**: الفعل المطلوب من اللاعب.
2. **كيف تنفذها؟**: الطريقة العملية.
3. **متى تنتهي؟**: شرط الاكتمال.
4. **القيد**: الوقت أو الجودة أو الأجر أو أي عامل يحد الاختيار.
5. **الحالة**: جارية، قرار مطلوب، استؤنفت، أو مكتملة.

إذا ظهر موقف جديد أثناء المهمة، يجب عرض التسلسل التالي بصريًا:

`فعل اللاعب أو تقدم المهمة → حدث أثناء/بعد المهمة → معنى الحدث → قرار مطلوب → نتيجة القرار → استكمال أو إكمال المهمة`

لا تستخدم عبارة «بسبب قرارك» إلا إذا كانت العلاقة السببية حقيقية داخل السيناريو. إذا كان الحدث وقع فقط أثناء المهمة، استخدم «أثناء تنفيذ المهمة». وإذا جاء بعد خطوة سابقة دون إثبات السببية، استخدم «بعد إكمال الخطوة السابقة».

الخيارات التي تمثل المهمة نفسها، مثل تصنيف عنصر بيانات، يجب أن توصف صراحة بأنها **اختيار لإكمال المهمة** وليست Incident.

## قواعد إظهار الأشخاص والجهات

- أي شخص يعطي أمرًا، يفرض موعدًا، يحذر العامل، يراجع عمله، يرفضه، أو يتأثر بقراره يجب أن يظهر بصريًا، لا كنص فقط.
- الشخصية الرئيسية تستخدم بطاقة الشخصية الكبيرة وصورتها الكرتونية.
- الشخصيات الثانوية والفرق تستخدم `actorStrip` أو `actorMessage` مع صورة ودور واضحين.
- المنصة أو النظام أو القيد المؤسسي لا يمثل بوجه بشري؛ يستخدم `institutionCard` بتصميم مختلف.
- لا تعتمد على الإيموجي وحدها لتمثيل شخص مشارك في القرار.

## `js/scenes/`

كل ملف يمثل مرحلة رئيسية واحدة. يحتوي على المشاهد والتفاعلات الخاصة بتلك المرحلة فقط.

عند إضافة مشهد جديد:

1. أضفه داخل ملف المرحلة المناسبة.
2. أعد الدالة ضمن كائن المسارات في نهاية الملف.
3. أضف الشخصية الرئيسية في `characters.js` إذا كانت مطلوبة.
4. أضف أي دور ثانوي مؤثر في `supporting-actors.js` ثم اربطه بالمشهد في `scene-guidance.js`.
5. عرّف المهمة في `stage-tasks.js` إذا كانت مرحلة جديدة.
6. أضف المشهد إلى مجموعة الخلفية في `stage-backgrounds.js`.
7. لا تضف الحالة إلى `DEFAULT_STATE` إلا إذا كان يجب حفظها بين إعادة تحميل الصفحة.

## CSS

- `variables.css`: المتغيرات فقط.
- `base.css`: العناصر الأساسية والطباعة.
- `layout.css`: هيكل الصفحة العام.
- `components.css`: المكونات العامة.
- `scenes.css`: عناصر اللعب الخاصة بالمشاهد.
- `characters.css`: صور وبطاقات الشخصيات.
- `task-flow.css`: المهمة والحدث والقرار والنتيجة والأشخاص الثانويون والجهات المؤسسية.
- `education.css`: مقدمات المراحل والخريطة التعليمية.
- `stage-backgrounds.css`: الخلفيات المرسومة.
- `accessibility.css`: أوضاع الوصول.
- `responsive.css`: قواعد الاستجابة العامة.

على الهاتف يبقى ملخص «مهمتك الآن» ظاهرًا في أعلى منطقة اللعب، بينما تختفي التفاصيل الثلاثة الطويلة لتقليل المساحة المحجوبة.

## قواعد عامة

- كل نص ديناميكي يمر عبر `escapeHtml` قبل حقنه في HTML.
- لا تستخدم قيمًا رقمية غير مقيدة في `style` مباشرة.
- لا تضف مكتبة خارجية لمشكلة يمكن حلها بواجهات المتصفح الأصلية.
- لا تعتمد على ترتيب عناصر القائمة لربط الشخصية بصورتها؛ استخدم بيانات الشخصية نفسها.
- حافظ على توافق بيانات `localStorage` عند إضافة حقول جديدة.
- لا تجعل فشل الصوت أو التخزين المحلي يمنع استمرار اللعبة.

## التحقق الآلي

يعمل Workflow باسم `Validate static game` على Pull Requests ويدقق:

- صياغة جميع ملفات JavaScript باستخدام Node.
- وجود ملفات CSS وJavaScript المحلية المشار إليها من `index.html`.
- مرور رحلة كاملة عبر Playwright على سطح المكتب والهاتف.
- ظهور لوحة المهمة في كل مرحلة.
- ظهور حدث واضح وعبارة «قرار مطلوب» في المواقف الشرطية.
- ظهور صور للشخصيات الثانوية عندما يكون لها دور في المشهد.
- بقاء لوحة المهمة Sticky على عرض الهاتف المستخدم في الاختبار.
