# بنية الكود

هذه الوثيقة تصف البنية الحالية للعبة وتحدد مصدر الحقيقة لكل مجال حتى لا تتراكم مسارات أو ملفات أو حالات متوازية.

## `index.html`

هيكل الصفحة الثابت: شريط اللعبة، حاويات المشهد، النوافذ الحوارية، ومراجع CSS وJavaScript. لا يوضع منطق المراحل هنا. `#scene` منطقة عادية وليست `aria-live` عامًا؛ الانتقال بين المشاهد يعتمد على إدارة التركيز.

## `js/app.js`

نقطة تشغيل التطبيق. يستعيد الحالة والإعدادات، يعرض إشعار migration/reset مرة واحدة عند وجوده، يربط الوحدات المشتركة، يسجل مسارات المشاهد، ويضيف طبقة الإرشاد الموحدة قبل محتوى كل مشهد.

## `js/core/`

- `state.js`: `STATE_SCHEMA_VERSION`، شكل الحالة الافتراضية، والمساعدات العامة.
- `storage.js`: semantic validation، migration من المخطط السابق، وحفظ الحالة والإعدادات في `localStorage`.
- `router.js`: الانتقال والرسم وإدارة التركيز.
- `decisions.js`: سجل القرارات السببية.
- `ledger.js`: دفتر السلسلة.
- `audio.js`: أصوات الواجهة الاختيارية.
- `accessibility.js`: تطبيق إعدادات الوصول.

لا يضاف إلى `DEFAULT_STATE` حقل يمكن اشتقاقه بسهولة من حالة أخرى. الحقل المحفوظ مطلوب فقط إذا كان القرار أو الأثر يجب أن يبقى بعد إعادة تحميل الصفحة أو يستخدم في مرحلة لاحقة.

## قواعد مخطط الحالة

- كل حالة محفوظة تحمل `schemaVersion`.
- validators تقيد enums والمصفوفات والنطاقات والعلاقات بين الحقول، وليس الأنواع فقط.
- `dataStatuses` و`dataChecks` متوازيان بالطول: الأول لحالة workflow والثاني للحقوق/الخصوصية/الملاءمة.
- `deployLoad` إما `null` أو ثلاث نسب مجموعها 100.
- migration تحول المخطط المعروف فقط. إذا لم يكن الحفظ صالحًا أو قابلاً للترحيل، يعاد البدء مع إشعار للمستخدم.

## `js/data/`

- `chapters.js`: المراحل الثماني ومفاهيمها وتسميات رحلة اللعب.
- `content-tasks.js`: عناصر البيانات والتصنيف والتقييم والدعم.
- `story.js`: عناصر سردية مشتركة مثل الطلب التجريبي.
- `characters.js`: الشخصيات الرئيسية وربطها بالمشاهد.
- `supporting-actors.js`: الأدوار البشرية الثانوية.
- `stage-tasks.js`: المهمة الأساسية وطريقة التنفيذ وشرط الانتهاء والقيد.
- `stage-backgrounds.js`: خريطة كل route إلى مرحلة العرض؛ تشمل مشاهد الخاتمة وتحدي نقل التعلم.

## `js/components/`

- `character-card.js`: الشخصيات الرئيسية وشبكتها.
- `progress.js`: تقدم **اللعب** ومقدمات المراحل؛ يستخدم `aria-current="step"` للمرحلة الحالية ويؤكد أن الترتيب ليس معمارية النظام.
- `abstraction.js`: اختزال العمل إلى ناتج تقني مختصر.
- `hud.js`: مؤشرات العرض.
- `dialogs.js`: النوافذ الحوارية.
- `task-flow.js`: لوحة المهمة والحالة والقيد.
- `scene-guidance.js`: يربط المشهد بالمهمة والتقدم الحالي.
- `supporting-role-strip.js`: تمثيل الأدوار التي تدخل القرار.

## `js/scenes/`

كل ملف يمثل مرحلة رئيسية. عند إضافة route جديد:

1. أعده من factory المرحلة.
2. أضفه إلى `SCENES_BY_STAGE`.
3. اربط الشخصية أو الدور الداعم إذا كان حاضرًا في الحدث.
4. لا تضف state محفوظًا إلا إذا كان سيستخدم بعد إعادة التحميل أو في مرحلة لاحقة.
5. أضف اختبارًا للحالة الطبيعية وللمسار الحدّي أو غير الموصى به إذا كان القرار يغير المنطق.

قواعد سببية خاصة:

- التعدين: تأجيل التحذير يمكن أن يقود إلى فحص إلزامي، لا إلى كلفة نصية فقط.
- مركز البيانات: نقل workload لا يغلق عطل الأصل؛ الإصلاح وإعادة الاختبار يسبقان حالة الجاهزية.
- البيانات: passage منفصل عن clearance.
- التدريب: هامش السعة يحسب فوق الحد الأدنى المعلن.
- الجاهزية: baseline gates منفصلة عن causal verification bundles.
- التشغيل: التوزيع المحفوظ يغير المرونة ولا يفسر سبب العطل تلقائيًا.

## CSS

ملفات CSS تبقى مقسمة حسب المسؤولية الحالية. لا يترك selector أو custom property أو `@keyframes` بعد حذف المكون الذي يستخدمه؛ `tests/css-integrity.mjs` يفحص ذلك.

## تبعيات التطوير

اللعبة بلا runtime dependencies. `package.json` يحتوي فقط أدوات الاختبار والتحقق بإصدارات مباشرة محددة: Playwright وaxe وESLint. تثبت هذه الأدوات في CI ولا تدخل إلى كود المستخدم النهائي.

## التحقق الآلي

### `tests/static-integrity.mjs`

يفحص الاستيرادات، الملفات والـexports غير المستخدمة، الأصول، ربط CSS، خريطة routes، ومراجع الدخول إلى كل مشهد.

### `tests/css-integrity.mjs`

يفحص selectors والمتغيرات والحركات غير المستخدمة.

### `tests/storage-schema.mjs`

يثبت semantic validation، رفض القيم غير المنطقية، migration من المخطط السابق، واحترام إعداد النظام لتقليل الحركة عندما لا يوجد اختيار محفوظ.

### `tests/smoke.mjs`

يغطي:

- رحلة كاملة على Chromium desktop وmobile.
- المسارات الحدية وغير الموصى بها مثل تمرير مادة بمشكلة غير محسومة وتأجيل فحص التعدين.
- إغلاق عطل التبريد قبل الجاهزية.
- حفظ توزيع الحمل واستخدام هامشه لاحقًا.
- baseline release gates والحزم السببية.
- تحدي نقل التعلم واختيار القرارات البارزة في النهاية.
- فحوص وصول مستهدفة عبر axe وإدارة التركيز و`aria-current` وغياب live region الشامل.
- smoke مختصر على Firefox وWebKit.

قبل الدمج يجب أن تنجح صياغة JavaScript وESLint والفحوص الثابتة ومخطط التخزين وCSS واختبارات المتصفح معًا.
