# بنية اللعبة الحالية

هذه الوثيقة تصف البنية الحالية فقط. تاريخ الجولات موجود في `AUDIT-HISTORY.md`.

## التطبيق

اللعبة تطبيق ثابت من HTML وCSS وJavaScript باستخدام ES modules، من دون backend أو قاعدة بيانات أو حساب مستخدم. `index.html` هي صفحة التشغيل الوحيدة، والحالة والإعدادات تحفظ في `localStorage`.

الحالة الحالية تستخدم `schemaVersion: 6`. تبقى مسارات migration للحفظ من v5 والإصدارات الأقدم لأنها توافق مستخدم حقيقي، وليست صفحات أو واجهات أو منطق تشغيل حاليًا. إذا تعذر إثبات سلامة تقدم قديم بعد تغير السببية، يعاد المستخدم إلى نقطة آمنة قبل التدريب بدل تحميل حالة غير متسقة.

## مصادر الحقيقة

- `js/app.js` — تركيب التطبيق، تسجيل routes، الإعدادات والخلفيات.
- `js/core/state.js` — شكل الحالة الافتراضية الحالية فقط.
- `js/core/storage.js` — التحقق من الحالة، العلاقات السببية، migration والحفظ.
- `js/domain/game-rules.js` — المصدر المشترك لقواعد المجال: الحوسبة، مسائل البيانات غير المحسومة، الفحوص الإضافية، سعات التشغيل، المرونة، والتحقق من الاستعادة.
- `js/data/stage-backgrounds.js` — ربط المشاهد بالمجموعات البصرية وترتيب `SCENE_ORDER`.
- `js/data/stage-tasks.js` — الهدف والقيد وشرط الانتهاء لكل مرحلة.
- `js/components/scene-guidance.js` — العرض المرئي للمهمة والتقدم، مع استهلاك قواعد المجال بدل نسخ الحسابات.
- `js/scenes/` — منطق كل مشهد والأحداث والقرارات والتنقل.

## مجموعات المشاهد

`SCENES_BY_STAGE` يفصل:

- `prelude`: البداية والانتقال من الواجهة.
- المراحل الثماني: mining إلى deployment.
- `ending`: تركيب النظام، الإجابة الأصلية، تحدي نقل التعلم، والنتائج.

في التقييم فُصلت مراجعة حوكمة البيانات عن مراجعة بوابات الإصدار وعن قرار الإصدار. وفي التشغيل فُصل توزيع الحمل عن اختبار المرونة وعن نافذة المراقبة بعد الإطلاق. هذا يجعل اسم route مطابقًا للمهمة الفعلية ويقلل الحالات الشرطية داخل شاشة واحدة.

## قواعد الحالة

يخزن النظام فقط ما يلزم لاستمرار السببية والتاريخ. من الأمثلة:

- `dataStatuses` لحالة مسار المادة.
- `dataChecks` لأدلة الحقوق والخصوصية والملاءمة المستقلة.
- `dataTrainingApproved / dataTrainingHeld` لقرار الأهلية.
- `dataCurrentTrainingUsed` للنسخة الحالية و`dataTrainingUsed` للتاريخ.
- `candidateRevision` لربط أدلة التقييم بنسخة مرشحة محددة.
- `factoryMaintenanceDebt / factoryRemediationStage` لفصل قرار الإنتاج عن التشخيص والإصلاح وإعادة القياس.
- `dcCoolingChoice / dcCoolingRestored` لفصل قرار الاستمرارية عن إغلاق عطل التبريد.
- `releaseGates / extraChecks / deferredExtraChecks / monitoringChecksCompleted` لتتبع العمل المفتوح والمنجز حول الإصدار.
- `deployLoad / deployFailoverChecks / deployTabs / deployRecovery / deployRecoveryDisposition` لتتبع التشغيل والاستعادة وأي خطر متبقٍ.

`trainingCompute` ليس جزءًا من schema v6. التخصيص الحالي ثابت عند 8 مجموعات في `game-rules.js`; قيم 8/12 القديمة تظهر فقط عند قراءة حفظ قديم ثم تختفي أثناء migration. وبالمثل لا تقبل الحالة الحالية قيم `transferChoice` القديمة؛ القيمة الحالية الوحيدة بعد إكمال تحدي النقل هي `build-use`.

سجل `decisions` تاريخ لما فعله اللاعب، وليس بديلًا عن حالة التشغيل. مثلًا، اختيار إيقاف التبريد يسجل فورًا في `dcCoolingChoice='stop'`، بينما `dcCoolingRestored=false` يظل دليلًا على أن الإصلاح لم يكتمل بعد.

## السببية في المعالجة والاستعادة

- المصنع: قرار الإيقاف لا يغلق تنبيه الجسيمات. الإغلاق يتطلب تشخيصًا، إصلاحًا، ثم إعادة قياس. ويمكن لمسار الاستمرار حمل دين الصيانة صراحة بدل إخفائه.
- مركز البيانات: النقل أو التوقف يحافظ على الاستمرارية أو يوقف الاختبار، لكنه لا يعيد المجموعة الأصلية إلى الخدمة قبل الإصلاح والتحقق وإعادة الاختبار.
- التدريب: 8 مجموعات قيد ثابت. عند خروج مجموعة يصبح القرار بين توقف واستعادة صريحة أو استمرار عند الحد الأدنى مع فحص استقرار إضافي.
- التشغيل: التوزيع الابتدائي صالح للحالة العادية لكنه لا يتحمل خروج مركز كامل. يختبر اللاعب الحالات الثلاث قبل قبول فجوة المرونة.
- الحادث: إعادة التشغيل تعني استعادة مؤقتة فقط. بعد التحقق يجب إما الرجوع إلى الإصدار السابق أو تسجيل الدين التشغيلي المتبقي تحت المراقبة. الدعم لا يبدأ قبل حسم هذا الوضع.

## قواعد المجال المشتركة

`js/domain/game-rules.js` هو المصدر الوحيد للحسابات والقواعد النقية المشتركة، ومنها:

- `MIN_COMPUTE_TO_CONTINUE` و`TRAINING_COMPUTE`.
- `hasUnresolved` ومشتقات حواجز البيانات.
- `neededExtraChecks` و`confirmedAnnotations`.
- `DEPLOY_CAPACITY_LIMITS` و`FAILOVER_INGRESS_LIMITS` و`MAX_SURVIVABLE_FAILURES`.
- `failoverCase` و`survivableFailures` و`hasResilienceResolution`.
- قواعد إثبات الاستعادة وإكمال disposition للحادث.

إذا تغيرت قاعدة حسابية، يجب تعديل المصدر المشترك لا إنشاء نسخة داخل `storage.js` أو أحد المشاهد.

## العرض والوضوح

- `character-card.js` — الشخصية الرئيسية، وتستمر بصريًا عبر شاشات القرار داخل المرحلة بدل الظهور في شاشة الدخول فقط.
- `supporting-role-strip.js` — الأدوار الداعمة عند دخولها قرارًا أو تنفيذًا؛ ويظهر منتجو المحتوى بصريًا قبل تجهيز البيانات.
- `abstraction.js` — يشرح كيف يختصر النظام العمل؛ لا يقول إن الناتج يتحول حرفيًا إلى المرحلة التالية.
- `progress.js` — تقدم المراحل ومقدماتها والمصطلحات العربية.
- `task-flow.js` — حالة «مهمتك الآن».

النتائج تصف القائمة الموسعة بأنها «أدوار بشرية تمثلها السلسلة» بدل الادعاء أن كل دور ظهر فعليًا في كل مسار. الأدوار الشرطية تضاف عندما تستدعيها قرارات اللاعب.

## الملفات القديمة

لا توجد صفحة تشغيل قديمة إلى جوار `index.html`. `persistentFooter` والأنماط المرتبطة به حُذفت سابقًا لأنها كانت مخفية دائمًا، و`ending.css` حُذف بعد نقل القواعد الحية، كما حُذف أصل صورة المشرف غير المستخدم. الجولة العاشرة تزيل البقايا القديمة من schema ومنطق التشغيل بدل إبقاء قيم تاريخية قابلة للاستخدام في الحالة الحالية.

مسارات migration ليست «كود إصدار قديم» قابلًا للحذف ما دامت هناك محفوظات محلية قد تعتمد عليها؛ وظيفتها الوحيدة تحويل تلك الحالات إلى schema v6 أو إعادة المستخدم إلى نقطة آمنة.

## الاختبارات

- `static-integrity.mjs`: الاستيرادات والملفات والـexports والأصول والمشاهد، ويشترط وجود `index.html` وحدها كصفحة HTML، ويمنع رجوع `trainingCompute` ونسخ قواعد المجال والمصطلحات القديمة المحددة.
- `storage-schema.mjs`: schema v6 والعلاقات السببية وترحيل v5 والإصدارات الأقدم.
- `css-integrity.mjs`: selectors وcustom properties وkeyframes.
- `smoke.mjs`: رحلات كاملة عبر المتصفح، causal checks، migration، axe، Firefox وWebKit.
- مجموعات `regression-*`: حوكمة البيانات، النسخ المرشحة، المرونة، الإرشاد، النتائج، الأدوار، والوضوح والمعالجة.

لا تنشئ وثيقة تحقق مستقلة لكل جولة؛ التاريخ موحد في `AUDIT-HISTORY.md` والاختبارات هي الحارس التنفيذي للتصميم الحالي.
