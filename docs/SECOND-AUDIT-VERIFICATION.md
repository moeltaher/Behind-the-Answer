# التحقق من جولة المراجعة الثانية

تسجل هذه الوثيقة المشكلات التي عالجتها جولة المراجعة الثانية، وما تغير في منطق اللعبة أو اختبارات التحقق بسبب كل مشكلة.

## 1. الجاهزية ليست بطاقة نصية

بوابات الإصدار الأربع أصبحت تتطلب مراجعة دليل منفصلة قبل فتح قرار الإطلاق: الانحدار، الأداء والسعة، السلامة/الأمن/الخصوصية، والمراقبة وخطة التراجع. عرض أسماء البوابات وحده لا يحسبها مكتملة.

## 2. ديون البيانات الحاجبة

المادة التي وصلت إلى التطوير مع مسألة حقوق أو خصوصية غير محسومة لا يمكن نقلها ببساطة إلى المراقبة بعد الإطلاق. يعرض السيناريو حاجب إصدار واضحًا، ويطلب إما حسم المسألة أو استبعاد المادة من الجولة. أما تحقق checkpoint والاستقرار فيمكن أن يبقى عملًا إضافيًا قابلًا للمراقبة بحسب قرار اللاعب.

## 3. اتساق الحالة المحفوظة

أضيفت invariants تربط الحقول ببعضها، ومنها ترتيب تجهيز الخادم، واتساق `dataIndex` مع المواد المعالجة، وتسلسل نتائج التصنيف، وعلاقة إصلاح السلامة بإعادة الاختبار، وحدود سعات مراكز البيانات، واكتمال التشخيص قبل تسجيل قرار الاستعادة. ترحيل الحفظ القديم يزيل الحالات التابعة التي لا يملك المخطط السابق مدخلاتها بدل الاحتفاظ بحالة مستحيلة.

## 4. التعلم من عمل التصنيف

بعد الوردية تظهر مراجعة مثالًا بمثال: اختيار العامل، والتصنيف الذي يدعمه دليل السيناريو، وسبب الحكم. يبقى قرار المراجع منفصلًا، ولذلك يمكن أن يظهر رفض قابل للنزاع رغم أن اختيار العامل متسق مع الدليل الذي كان متاحًا له.

## 5. checkpoint كفرضية قابلة للاختبار

قبل اختبار السلامة يرى اللاعب عينة تقييم مختلطة مرتبطة بتغيير checkpoint، ولا يستطيع متابعة بوابة السلامة قبل أن يميز بين «التغيير أحدث» وبين «لدينا دليل كافٍ على أنه أفضل». الهدف هو جعل التقييم اختبارًا للفرضية لا أثرًا نصيًا للاختيار.

## 6. دين صيانة المصنع

إذا استمرت الدفعة مع تشديد الفحص، يبقى تحقيق سبب ارتفاع الجسيمات مسجلًا باعتباره دين صيانة مفتوحًا. وإذا توقف الخط للتحقيق، يسجل إغلاق السبب داخل المرحلة. مرور وحدات بالفحص لا يمحو حالة الصيانة.

## 7. نقل التعلم

تحدي النهاية لم يعد اختيارًا بين إجابة صحيحة وخيارات كاريكاتورية. يصنف اللاعب عناصر من خدمة مختلفة تستخدم RAG إلى: ما بُني قبل الطلب، وما يحدث بسبب الطلب الحالي، وما يستمر أثناء التشغيل حتى خارج لحظة الطلب.

## 8. ما يحدث وقت الطلب

توضح الخاتمة أن بعض المنتجات قد تضيف routing أو retrieval أو moderation أو tool calls أو caching أو logging عند الطلب، من دون الادعاء بأن كل منتج يستخدم هذه المكونات. يبقى الفصل الأساسي قائمًا بين بناء النظام سابقًا واستخدام بنية قائمة عند الطلب.

## 9. عدم اختراع إعادة محاولة

مسار `restart` لا يعلن عددًا محددًا لمحاولات المستخدم إذا لم تقع إعادة المحاولة داخل اللعب. تعرض الخاتمة حالة استعادة الخدمة فقط والمخاطرة المتبقية من استمرار الإصدار المشتبه به.

## 10. هامش السعة

يعرض التشغيل الآن إجمالي headroom، وأكبر هامش في موقع واحد، وهوامش المواقع الثلاثة، بدل استخدام عدد المواقع ذات الهامش الموجب وحده باعتباره وصفًا كافيًا للمرونة.

## 11. وصول الحوارات والمناطق القابلة للتمرير

كل `<dialog>` مرتبط بعنوان صريح عبر `aria-labelledby`. وتغطي اختبارات axe أسماء الحوارات بعد فتحها. كما أصبحت خرائط التقدم الأفقية القابلة للتمرير مناطق مسماة يمكن الوصول إليها بلوحة المفاتيح.

## 12. فشل الحفظ المحلي

تعيد وظائف حفظ الحالة والإعدادات نتيجة نجاح أو فشل. إذا تعذر `localStorage` تعرض الواجهة تحذيرًا واضحًا بأن الجلسة يمكن أن تستمر لكن الاستئناف لاحقًا غير مضمون.

## 13. تشخيص CI

أزيل التصنيف المعتمد على أرقام أسطر ثابتة في `tests/smoke.mjs`. أصبحت الرحلات والاختبارات تطبع أسماء مراحل ثابتة، كما أصبحت جولة المراجعة الثانية مجموعة regression مستقلة `tests/second-audit.mjs`.

## مصفوفة التحقق

- `npm audit --audit-level=high`: تدقيق تبعيات التطوير.
- `npm run check:syntax`: سلامة JavaScript.
- `npm run check:lint`: المتغيرات غير المستخدمة ومشكلات lint المحددة.
- `npm run check:static`: الملفات والمراجع والـroutes والأصول والحالة غير المستخدمة.
- `npm run check:storage`: schema + semantic validation + cross-field invariants + migration + storage failures.
- `npm run check:css`: مراجع CSS والمتغيرات.
- `npm run test:browser`: رحلة كاملة desktop/mobile، اختبارات السببية، axe كامل على مشاهد مختارة، وFirefox/WebKit smoke.
- `npm run test:second-audit`: regression مخصص للمشكلات الثلاث عشرة في هذه الجولة، بما فيها blockers والبوابات والتصنيف ونقل التعلم والحوارات.
